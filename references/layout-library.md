# 布局库（Layout Library）

> 本库是 **axi-front-design 执行层**的页面布局素材库。**41 个布局** = 10 个叙事风（A1–A10）+ 22 个事实风（B1–B22）+ 9 个 Bento 网格（C1–C9）。
> 结构模式蒸馏自 guizang-ppt-skill（AGPL-3.0）与 ppt-agent（无 LICENSE）的设计理念，代码全部用合集自己的 design token 体系重写，**不复制其模板/类名/代码**。

## 使用方式

1. 生成页面时，先看**数据护照**里的内容形状（是数据还是论断？几项对等？有无时间轴？）
2. 用文末**「选版式决策表」**选定布局
3. 按该布局的线框 + 结构 + 尺寸规则实现，类名由 axi-front-design 自行定义
4. 遵守文末**「主题节奏硬规则」**和**「反 AI 俗套」**

## 设计 token 基线（合集自有，所有布局共用）

| token | 值 |
|-------|-----|
| 画布 | 1920×1080，`.slide` 容器，`.slide:not(.active){display:none!important}` |
| 主标题 H1 | 88–120px，封面大字，≤ 2 行 |
| 页内标题 H2 | 64–80px，≤ 3 行 |
| 栏目/卡片标题 H3 | 32–44px |
| 正文/列表 | 22–28px，绝不低于 20px |
| meta/mono 标签 | 16–20px |
| 背景节奏 | 1-2 种底色，禁连续 3 页同色 |
| 字体 | 由数据护照指定；禁 Inter/Roboto/Arial 默认 |
| 反俗套 | 无渐变背景、无 emoji 图标、无圆角卡片+左边框、无 accent stripe、无 SVG 手画插画 |

**字号越大越细原则**（事实风核心）：同一页内，字号越小的元素字重必须 ≥ 字号越大的元素；16px 左右小字最低 weight 400（推荐 500），封面大字可用 weight 200–300。

**中文标题字号分档**（中文方块字视觉面积更重，不能直接套英文字号）：
| 中文标题形态 | 推荐字号 |
|---|---|
| 1 行，≤ 8 字 | `min(6.4vw, 11.2vh)` |
| 2 行，每行 ≤ 8 字 | `min(5.8vw, 10.2vh)` |
| 2 行，任一行 9–12 字 | `min(5.2vw, 9.2vh)` |
| 3 行或更长 | 改写标题；不能改时 `min(4.6vw, 8.2vh)` |

**双约束限高**：大字号永远写 `min(Xvw, Yvh)`，且 Y ≥ X × 1.6（标准 16:9 屏 1vw:1vh≈1.78，Y 太严会被高度截断）。

# Part 1 · 叙事风（10 布局）

**整体气质**：像杂志贴上了代码，适合叙事、观点、分享、个人风格表达。留白多、层级靠字号对比而非装饰、图片是第一公民。

**主题节奏默认**：开场封面 `hero dark`，章节幕封 `hero light`/`hero dark` **必须交替**，数据大字报 `light`，左文右图 `light`/`dark` **交替**，图片网格 `light`，Pipeline `light`，问题页 `hero dark`，大引用 `dark` 优先，对比页 `light`，图文混排 `light`/`dark` **交替**。

## A1 · 开场封面（Hero Cover）

- **用途**：整套 deck 起手页 / 主题宣言
- **适用内容**：纯文字结构（主标题 + 副标 + 一句引子 + 作者信息），不承载数据

```
┌────────────────────────────────────────────┐
│ 上下文标签 · 日期            Vol.01         │  ← chrome 页眉
│                                            │
│                                            │
│        kicker 引导句                        │
│        主标题（最大字号，垂直居中）           │
│        副标题                              │
│        引子段落（max-width 60%）            │
│        作者 · 身份                          │
│                                            │
│ 页脚说明                     — 2026 —       │  ← foot 页脚
└────────────────────────────────────────────┘
```

- **结构**：`.chrome` 页眉（左栏目标签 / 右页号）→ 主内容区（flex column 垂直居中）→ `.foot` 页脚
- **规则**：主标题用全页最大字号（约 10vw）；内容区 `min-height:80vh + 垂直居中`；引子限宽 60vw；封面页 `.chrome` 可不写页号

## A2 · 章节幕封（Act Divider）

- **用途**：章节/幕开场，呼吸节奏
- **适用内容**：极简，只需栏目名 + 大标题 + 一行引语

```
┌────────────────────────────────────────────┐
│ 第一幕 · 硬数据             Act I · 01/25   │
│                                            │
│                                            │
│        kicker: Act I                        │
│        章节大标题                           │
│        一行引语                             │
│                                            │
│                                            │
│ 第一幕引子                     — · —        │
└────────────────────────────────────────────┘
```

- **结构**：kicker → 大标题 → 一行 lead，整体垂直居中
- **规则**：相邻两个幕封 `hero light`/`hero dark` **必须交替**；大标题字号可 8.5vw 适配长短

## A3 · 数据大字报（Big Numbers Grid）

- **用途**：抛硬数据制造冲击
- **适用内容**：4–6 个关键数字/指标，必须有真实数值
- **默认主题**：`light`（数字需纸白底）

```
┌────────────────────────────────────────────┐
│ 过去 64 天 · 开发篇         Act I · 02/25   │
│ kicker: 一个人，做了什么。                  │
│ H2 标题                                     │
│ lead 说明                                   │
│ ┌───────┬───────┬───────┐                  │
│ │label  │label  │label  │  3×2 网格        │
│ │ 64 天 │ 110K+ │ 5,166 │                  │
│ │ note  │ note  │ note  │                  │
│ ├───────┼───────┼───────┤                  │
│ │label  │label  │label  │                  │
│ │ 41K+  │  19   │ 608+  │                  │
│ │ note  │ note  │ note  │                  │
│ └───────┴───────┴───────┘                  │
│                                            │
│ 项目 · CodePilot          Act I · Dev       │
└────────────────────────────────────────────┘
```

- **结构**：kicker → H2 标题 → lead → 3×2 网格。每个 stat-card 结构固定：`label`（英文小字）→ `数值`（大字）→ `note`（注释）
- **规则**：数值建议 2–3 位字符（太长溢出），用 K/M 简写；间距不要放大——标题 3vh 留白 + lead 2vh + 网格 2vh 是 16:9 屏不压页脚的实测上限；内容更多时**删卡片**，不要压缩页脚空间

## A4 · 左文右图（Quote + Image）

- **用途**：讲一个观点时配一张图，身份反差/挂钩
- **适用内容**：一个核心论点 + 一张核心图片
- **默认主题**：`light`/`dark` 交替

```
┌────────────────────────────────────────────┐
│ 身份反差 · The Twist         03 / 25       │
│ ┌───────────────┬──────────────────────┐   │
│ │ kicker: BUT   │  ┌────────────────┐  │   │
│ │ 我不是程序员   │  │  image 16:10    │  │   │
│ │ lead 说明     │  │  (右列)         │  │   │
│ │              │  │                │  │   │
│ │ callout 引用  │  │  caption       │  │   │
│ │              │  └────────────────┘  │   │
│ └───────────────┴──────────────────────┘   │
│ 左 7 份          右 5 份                    │
│ Page 03 · ...                — · —         │
└────────────────────────────────────────────┘
```

- **结构**：`grid 7:5` 两列。左列 flex column：kicker → H2 标题 → lead → callout（引用贴底）；右列图片
- **规则**：左列用 `justify-content:space-between`（标题贴顶、callout 贴底）；右列图片**禁止 `align-self:end`**（会滑到 cell 底部被工具栏遮挡）；图片必须标准比例（16:10 / 4:3），不要用原图奇葩比例

## A5 · 图片网格（多图对比）

- **用途**：证据支撑，多图并列
- **适用内容**：3–6 张同类型图片/截图
- **默认主题**：`light`

```
┌────────────────────────────────────────────┐
│ 平台粉丝实证                 Act I · 05/27  │
│ kicker: Proof · 粉丝实证                   │
│ H2: 10 个平台 · 6 张截图                   │
│ ┌──────┬──────┬──────┐                    │
│ │ img  │ img  │ img  │   3×2，统一高度    │
│ │ cap  │ cap  │ cap  │   26vh             │
│ ├──────┼──────┼──────┤                    │
│ │ img  │ img  │ img  │                    │
│ │ cap  │ cap  │ cap  │                    │
│ └──────┴──────┴──────┘                    │
│ 截图时间 · 2026.04        Page 05 · ...    │
└────────────────────────────────────────────┘
```

- **结构**：kicker → H2 → `3×2` 网格，每个 `figure.frame-img` 内图片 + 图注
- **规则**：每个图片容器**必须写死高度**（`height:NNvh`，3×2 双行上限 26vh），不要用 `aspect-ratio`，否则网格撑破；图注显示在框内底部（有图注时图片实际展示高度 ≈ NNvh − 4vh）；同组必须同一高度

## A6 · 双列流水线（Pipeline）

- **用途**：展示工作流/流程
- **适用内容**：2 组并行的步骤序列（每组 ≤5 步）
- **默认主题**：`light`

```
┌────────────────────────────────────────────┐
│ 我的工作流 · Workflow        Act II · 15/27 │
│ kicker: Pipeline · 流水线                  │
│ H2: 两条流水线                             │
│ ── 文本侧 · Text Pipeline ──               │
│  [01 Draft] [02 Polish] [03 Morph] [04..]  │
│ ── 视觉 · 视频侧 · Video ──                │
│  [06 Cut] [07 Wrap] [08 Cover]             │
│                                            │
│ Page 15 · 我的内容工厂       Workflow       │
└────────────────────────────────────────────┘
```

- **结构**：`.pipeline-section` 分组（组标题 + 水平步骤行），每组步骤结构固定 `编号 → 标题 → 一行描述`
- **规则**：两组间距 3.6vh + 顶部细分隔线；单行 ≤5 步，超过换第二组

## A7 · 悬念问题页（Hero Question）

- **用途**：幕收束、留悬念
- **适用内容**：一个核心问题 / 悬念陈述
- **默认主题**：`hero dark`

```
┌────────────────────────────────────────────┐
│ 留给你的问题                  24 / 27      │
│                                            │
│                                            │
│        kicker: The Question                │
│        大问题（3 行以内，手工断行）          │
│                                            │
│        一行点破                            │
│                                            │
│ Page 24 · The Question        — · —        │
└────────────────────────────────────────────┘
```

- **规则**：留白越多越好，只放一个问题；大标题字号按行数调（3 行约 7vw，1 行约 10vw）；用 `<br>` 手工断行确保断点在语义处；尾巴可给一行 lead 点破

## A8 · 大引用金句（Big Quote）

- **用途**：核心金句/金句墙
- **适用内容**：一句值得放大展示的引语 + 出处
- **默认主题**：`dark` 优先，偶用 `light`

```
┌────────────────────────────────────────────┐
│ The Takeaway · 核心金句        18 / 25     │
│                                            │
│        "没有交接,                           │
│         所有人都在构建。"                    │
│                                            │
│        Without the handoff...（英文原文）   │
│        — 出处 · 日期                        │
│                                            │
│ Page 18 · 金句                 — · —        │
└────────────────────────────────────────────┘
```

- **规则**：整页留白；引用句独立放大（5–6vw 衬线），**不要**用页面主标题类名；下方英文原文降低透明度（~0.65）制造层级；配出处行

## A9 · 并列对比（Before / After）

- **用途**：旧/新、A/B 范式转变
- **适用内容**：二元对照（必须正好 2 项）
- **默认主题**：`light`

```
┌────────────────────────────────────────────┐
│ 旧 vs 新 · The Shift          12 / 25     │
│ kicker: Before / After · 范式转变          │
│ H2: 从交接到共建                           │
│ ┌──────────────────┬──────────────────┐   │
│ │ Before · 旧模式  │ After · 新模式   │   │
│ │ 标题             │ 标题             │   │
│ │ ▸ 要点           │ ▸ 要点           │   │
│ │ ▸ 要点           │ ▸ 要点           │   │
│ │ （半透明弱化）    │ （满亮度突出）    │   │
│ └──────────────────┴──────────────────┘   │
│ 1:1 均分，中间分隔                           │
│ Page 12 · 范式转变          Before/After    │
└────────────────────────────────────────────┘
```

- **结构**：`grid 1:1` 左右分半，两列结构统一 `kicker → 标题 → 要点列表`
- **规则**：旧侧半透明（~0.55）视觉弱化，新侧满亮度；两列用左侧竖线 + 内边距做引用块感

## A10 · 图文混排（Lead Image + Side Text）

- **用途**：信息量偏大的页面（多层级内容 + 一张辅助图）
- **适用内容**：大段正文/说明 + 一张竖版或方形小图
- **默认主题**：`light`/`dark` 交替

```
┌────────────────────────────────────────────┐
│ Design First · 设计先行        08 / 16     │
│ ┌────────────────────┬───────────────┐    │
│ │ kicker: Phase 01   │  ┌─────────┐  │    │
│ │ H2: 设计先行 · 2周  │  │ img 3:4 │  │    │
│ │ lead 说明           │  │ (竖版)   │  │    │
│ │ 正文段落            │  │         │  │    │
│ │ callout 引用        │  │ caption │  │    │
│ │                    │  └─────────┘  │    │
│ └────────────────────┴───────────────┘    │
│ 左 8 份               右 4 份               │
│ Page 08 · Design First       约 2 周       │
└────────────────────────────────────────────┘
```

- **结构**：`grid 8:4`，左列正文主导（kicker → 标题 → lead → 段落 → callout），右列辅助小图
- **规则**：右列图片用竖版 3:4 或方形 1:1，避免和左列文本竞争注意力；适合信息量偏大的页（不像 A4 只有一句金句）

# Part 2 · 事实风（22 布局）

**整体气质**：瑞士国际主义——网格至上、单一高饱和锚点色、直角、发丝线、极致字号对比，适合事实、产品、分析、方法论表达。

**硬约束（P0，违反 = 整页报废）**：
1. **不做二次水平 padding**：页面容器自带 `5.6vh 5vw 4.4vh` padding，主体子元素共用同一条 5vw 边线，主体那层 `padding:0`，间距靠 grid `gap`
2. **kicker 必须在大标题上方**，上下结构（flex column），不能压成左右
3. **大字号永远 `min(Xvw, Yvh)` 双约束**，且 Y ≥ X × 1.6
4. **子元素间距用 grid `gap`**，禁在每个子块加 `margin-top`/`padding-top` 调间距
5. **底部 nav 安全区**：主内容最低处距底部 ≥ 8vh（`--nav-safe-bottom`），留至少 3vh 呼吸
6. **直角**：禁 `border-radius`；**卡片填充类型互斥**：ink 黑底 / accent 蓝底 / 灰底 / 描边 四选一，禁混用
7. **图标**：禁手画 SVG 图标，用 lucide 线库；**SVG 只画几何，不写可见文字**，标签放 HTML

**最小字号**：正文 ≥ 18px；卡片描述/列表/图注 ≥ 16px；meta/kicker/标签 ≥ 14px。内容过多先压文案/拆页/换版式，禁止靠缩小字号解决拥挤。

**动效原则**：每页一个与图形语义耦合的 recipe（数字 scale 弹入、bar scaleY 拉起、时间线节点序列点亮），不是统一 fade-up；缓动用 `cubic-bezier(.2,0,.38,.9)`（productive 120-240ms）/ `cubic-bezier(0,0,.3,1)`（expressive 400-700ms）。

## B1 · 封面页（Cover）

- **用途**：整套 deck 起手 / 主题宣言
- **适用内容**：纯文字（主标题 + 副标 + 元信息），不承载数据
- **默认**：满屏锚点色 + 呼吸场背景，或 左墨色/右纸白 对开

```
┌────────────────────────────────────────────┐
│ [标题 · 编号]                 SS · 01/NN   │
│                                            │
│        章节英文                            │
│        中文主标题（巨字，可斜体微强调）      │
│                                            │
│        副标 / 引子（1-2 行）                 │
│        作者 · 日期             → 翻页       │
└────────────────────────────────────────────┘
```

- **规则**：主标题反白 weight 200，强调字用斜体 weight 300 而非锚点色（底已是锚点色，同色看不见）；**不要**再放编号大字（页眉已标 01/NN）；与收束页 B9 形成"开场全锚点色 ↔ 收尾半锚点色"色彩闭环

## B2 · 纵向时间轴（Vertical Timeline）

- **用途**：演化对比、年代变迁、版本迭代
- **适用内容**：2–5 个带量化数据的时间节点（每节点必须有「年份 + 量化数值 + 描述」三件套）
- **无数据时**：改用 B11 横向时间线

```
┌────────────────────────────────────────────┐
│ [标题]                       SS · 02/NN    │
│ ● 2023  1×   Prompt Era                    │
│   ·                                       │
│   · 2024  4×   Agent Era                   │
│   ·                                       │
│ ● 2025  12×  Skill Era                    │
│                                            │
│ 轴列固定 12px · 虚线贯穿                     │
└────────────────────────────────────────────┘
```

- **结构**：左侧固定轴列（圆点绝对定位对齐虚线）+ 右侧节点信息（年份 + 大字数据 + 描述）
- **动效**：节点按时间顺序自上而下点亮（dot 先 pop 再扩 → 文字横向滑入）

## B3 · 极简陈述（Statement）

- **用途**：中心论点、章节起始、口号
- **适用内容**：纯定性论断 / 口号，一句话 8–12 词，**不承载任何数据或列表**
- **数据支撑**：需数据的论断改用 B18
- **封面**：是封面用 B1

```
┌────────────────────────────────────────────┐
│ [标题]                       SS · 03/NN    │
│                                            │
│     Build it once.                         │
│     It runs forever.                       │
│                                            │
│     — Statement 03                         │
│ ──────────────────────────────            │
└────────────────────────────────────────────┘
```

- **结构**：左 1/3 空白 + 中段巨字陈述（8–10vw weight 200）+ 右下小字注脚 + 底部 hairline
- **动效**：大字按词序错峰升起（每词延迟 180ms）+ 注脚淡入

## B4 · 六格定义（Six Cells）

- **用途**：6 个并列概念/功能定义
- **适用内容**：数量必须 = 6（过少用 B5，过多用 B15/B16）。每格仅「图标 + 编号 + 短标题 + 一行描述」
- **不承载**：需展开的数据/段落

```
┌────────────────────────────────────────────┐
│ [标题]                       SS · 04/NN    │
│ ┌─────┬─────┬─────┐                       │
│ │icon │icon │icon │   2×3                 │
│ │ 01  │ 02  │ 03  │                       │
│ │Skill│Data │Plan │                       │
│ ├─────┼─────┼─────┤                       │
│ │icon │icon │icon │                       │
│ │ 04  │ 05  │ 06  │                       │
│ └─────┴─────┴─────┘   hairline 分隔        │
```

# 主题节奏硬规则（生成后自检）

- ❌ **禁止**连续 3 页以上相同主题（包括 light 堆叠和 dark 堆叠）
- ❌ **禁止** 8 页以上的 deck 没有至少 1 个 `hero dark` + 1 个 `hero light`
- ❌ **禁止**整个 deck 只有 light 正文页没有任何 dark 正文页——会显得平淡没呼吸
- ✅ **推荐**每 3–4 页插入 1 个 hero（封面/幕封/问题/大引用）
- ✅ 事实风 deck 的版式多样性：7–8 页至少用 **6 个不同 B 编号**，不允许连续 3 页同一种主体结构；测试 deck 必须覆盖封面、收尾、至少 1 个对比/时间线（B8/B11/B2）、至少 1 个结构图（B14/B17/B15）、至少 1 个图片版式（B22 或 B15/B16 图片格）

# Part 3 · Bento Grid（9 布局）

**整体气质**：便当网格——卡片大小由内容重要性驱动，大卡 = 更重要的内容，现代感强。源自 Apple 的 Bento 布局风格，蒸馏自 ppt-agent（zengwenliang416，无 LICENSE，仅吸收通用布局模式）。

> ⚠️ **与 A/B 系列的差异**：Bento 卡片**用圆角 + 阴影**（`--radius` / `--shadow` 按设计系统 token），这与事实风 B 系列"直角无阴影"不同。Bento 是**独立的卡片式布局族**，选它时用叙事风/特效主题更协调。

**画布**：16:9，安全区四周 60px padding，12 列网格，最小卡距 20px。

**核心原则**：
1. **灵活**：卡片大小由内容重要性驱动，不是硬网格
2. **层级**：大卡 = 重要内容，尺寸传达优先级
3. **留白**：最小 20px 卡距，留白是设计元素不是浪费
4. **平衡**：视觉重量均匀分布
5. **节奏**：大卡小卡交替制造视觉节奏

**卡片宽高比约束**：最小 1:2（宽:高），最大 4:1；优先 16:9、4:3、1:1、3:4。

**卡片构成**：背景（圆角+阴影）+ 24px 内边距 + 标题（加粗大字）+ 内容 + 页脚（来源/标签，可选）。

**卡片内字号**：卡片标题 24-32px；卡片正文 16-20px；卡片标签 12-14px（大写/弱化）；大数字 48-72px（accent 色，统计卡）。

**内容自适应**：
| 内容量 | 适应 |
|---|---|
| 单个指标（1 数字+标签） | 大数字式：48-72px 居中 + 下方标签 |
| 短文本（<30 词） | 标准：16-20px 正文，24px 内边距 |
| 中文本（30-80 词） | 正文降到 16px，内边距 20px |
| 长文本（>80 词） | 正文降到 14px，内边距 16px |
| >5 条要点 | 拆成卡内两列 |
| >8 条要点 | 拆到两张卡 |

**构图引导**：非对称布局优先黄金比例（62:38）；最重要元素放三分点交点；强调卡（accent 背景+白字）每页 ≤2 个。

**数据卡规则**：
- 指标卡：大数字式，2-4 个一行
- 图表卡：最小宽度 300px，周边留 32px
- 对比卡：水平条排名，统一基线
- 趋势卡：迷你折线 + 指标同卡（迷你图在数字下方，60-80px 高）
- 用途选型：展示数字→大数字卡；展示趋势→迷你折线；比较→水平条；>10 条→表格卡

## C1 · 单焦点（Single Focus）

- **用途**：标题页、关键引用、hero 图、单个统计
- **适用内容**：一个主体，无分栏

```
┌─────────────────────────────────────┐
│                                     │
│              MAIN CONTENT           │
│                                     │
└─────────────────────────────────────┘
```

- 一张大卡占满可用区

## C2 · 双列对称（2-Column Symmetric）

- **用途**：对比、before/after、pros/cons
- **适用内容**：两个对等主体

```
┌───────────────┐ ┌───────────────┐
│               │ │               │
│    LEFT       │ │    RIGHT      │
│               │ │               │
└───────────────┘ └───────────────┘
```

- 两张等宽卡并排

## C3 · 双列非对称（2:1 / 1:2）

- **用途**：主内容 + 侧栏、图表 + 关键指标
- **适用内容**：主体 + 辅助

```
┌─────────────────────┐ ┌───────┐
│                     │ │       │
│     MAIN (2/3)      │ │ SIDE  │
│                     │ │ (1/3) │
└─────────────────────┘ └───────┘
```

- 一张宽卡 + 一张窄卡，主辅分明

## C4 · 三列均分（3-Column）

- **用途**：三个要点、三向对比、功能格
- **适用内容**：三个对等主体

```
┌─────────┐ ┌─────────┐ ┌─────────┐
│         │ │         │ │         │
│  COL 1  │ │  COL 2  │ │  COL 3  │
│         │ │         │ │         │
└─────────┘ └─────────┘ └─────────┘
```

- 三张等宽卡

## C5 · Hero + 网格（Hero + Grid）

- **用途**：主观点 + 支撑细节、数据总览 + 拆解
- **适用内容**：一个主体 + 2-3 个辅助

```
┌─────────────────────┐ ┌───────┐
│                     │ │ SMALL │
│     HERO (2/3)      │ ├───────┤
│                     │ │ SMALL │
└─────────────────────┘ └───────┘
```

- 一张 hero 大卡 + 2-3 张小卡（右侧或下方堆叠）

## C6 · 混合网格（L 形 / T 形）

- **用途**：仪表盘、多指标展示、功能展示
- **适用内容**：多种大小的内容混合

```
┌─────────────────────┐ ┌───────┐
│                     │ │       │
│     LARGE           │ │ TALL  │
│                     │ │       │
├───────────┬─────────┘ │       │
│   SMALL   │  MEDIUM   │       │
└───────────┴───────────┴───────┘
```

- 不规则但平衡的卡片网格，节奏感最强

## C7 · 时间线 / 流程（Timeline / Process）

- **用途**：项目里程碑、产品演进、历史时间线
- **适用内容**：顺序步骤（≤5 步）

```
┌─────────────────────────────────────┐
│  ●───────●───────●───────●───────● │
│  Step 1  Step 2  Step 3  Step 4  Step 5
│  [desc]  [desc]  [desc]  [desc]  [desc]
└─────────────────────────────────────┘
```

- 水平连接节点的流程卡

## C8 · 仪表盘 / 马赛克（4-6 卡）

- **用途**：KPI 仪表盘、多指标总览
- **适用内容**：4-6 个等权指标卡

```
┌─────────┐ ┌─────────┐ ┌─────────┐
│  CARD 1 │ │  CARD 2 │ │  CARD 3 │
├─────────┤ ├─────────┤ ├─────────┤
│  CARD 4 │ │  CARD 5 │ │  CARD 6 │
└─────────┘ └─────────┘ └─────────┘
```

- 2×2 或 2×3 等尺寸指标卡

## C9 · 上下分栏（Horizontal Split）

- **用途**：大标题 + 支撑指标、引用 + 证据
- **适用内容**：上部主体 + 下部细节行

```
┌─────────────────────────────────┐
│         HEADER / HERO           │
├───────────┬─────────┬──────────┤
│  DETAIL 1 │ DETAIL 2│ DETAIL 3 │
└───────────┴─────────┴──────────┘
```

- 上部 hero 卡 + 下部 3 列细节行

# 反 AI 俗套清单（两个风格都适用）

> **合集反俗套清单的权威版本。** 本清单 + `ppt-workflow` 禁止项互补充：layout-library 侧重布局/排版/细节规则，ppt-workflow 侧重流程级禁止项。两份加起来是全集禁止底线。

- ❌ 给卡片加 `border-radius` → ✅ 直角
- ❌ 在 accent 卡上又加描边 → ✅ 卡片填充类型互斥
- ❌ 自己手画 SVG 图标 → ✅ 用 lucide 线上库，棱角风格
- ❌ 时间线 dot 用 grid `justify-self` 对齐虚线 → ✅ 轴列固定 12px + dot 绝对定位
- ❌ 大字号不限高（`13vw`）→ ✅ 永远 `min(Xvw, Yvh)` 双约束
- ❌ 所有页用同一个 fade-up recipe → ✅ 每页一个语义化 recipe，与图形耦合
- ❌ 标题 + 卡片间距 < 5vh → ✅ 章节级标题至少 9vh
- ❌ 9px 圆形装饰点 → ✅ 8×8 直角小方块 / mono 文字
- ❌ 装饰元素超出页面边距 → ✅ 严格在 grid 内，不贴边
- ❌ 每页都是白底 → ✅ 用 1-2 种底色制造节奏
- ❌ 数据页无来源 → ✅ 加来源，每个数字主张都要归属
- ❌ 全 deck 只用 light 没有 dark → ✅ 每 3-4 页插一个 hero/幕封/问题页
- ❌ 卡片填充类型混用（ink/accent/灰底/描边四选一）→ ✅ 互斥
